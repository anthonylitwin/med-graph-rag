# MedGraphRAG Capstone Report Package

## What the project actually does to the data

Evidence labels used below: **Verified** means directly supported by code or saved artifacts; **Inferred** is a defensible design interpretation; **Future** is not currently implemented.

1. **Selects a topic-focused PMC corpus.** **Verified:** the benchmark list contains 30 PMC identifiers centered on lipids, cardiovascular disease, statins, fibrates, and omega-3 therapies. The current non-instruction ingestion manifest records 28 successful articles and two BioC-unavailable articles. Inputs are normalized PMC IDs, not arbitrary web documents (`data/source_documents/benchmark_pmcids.txt`; `pipelines/ingestion/pmc_inputs.py`, `collect_pmcids`).

2. **Acquires BioC JSON.** **Verified:** for each PMCID, `fetch_pmc_bioc` requests NCBI's PMC Open Access BioC endpoint, trying Unicode and then ASCII JSON, with retry/backoff for selected HTTP and network errors (`pipelines/ingestion/pmc_bioc.py`, `get_pmc_bioc_urls`, `fetch_pmc_bioc`). The complete response is retained under `raw/<PMCID>.json`.

3. **Converts BioC passages into a document record and contiguous text.** **Verified:** `parse_bioc_payload` uses the first BioC document and creates in-memory records for PMCID, PMID when present, title, year, journal, DOI, authors, source URL, and passage section/type/source offset. Passage whitespace is collapsed and nonempty passage text is joined with blank lines. The processed artifact carries derived chunk offsets/sections rather than the original passage source offsets; existing BioC annotations, relations, and sentence objects are not propagated (`pipelines/ingestion/pmc_bioc.py`, `clean_text`, `parse_bioc_payload`).

4. **Segments the cleaned article into overlapping character windows.** **Verified:** the main ingestion path defaults to at most 6,000 characters with 500-character overlap. It prefers a space after 60% of the maximum window and stores chunk ID, order, character offsets, primary section/type, all overlapping source sections, and text (`pipelines/ingestion/models.py`; `pipelines/ingestion/chunking.py`, `_split_text_spans`, `chunk_article`).

5. **Detects five biomedical entity types.** **Verified:** the deployed default profile, `local-non-instruct`, sends each chunk to `Ihor/gliner-biomed-small-v1.0` with labels Drug, Condition, Symptom, RiskFactor, and Biomarker and a default threshold of 0.50 (`packages/llm/profiles.py`; `pipelines/ingestion/extractors.py`, `GLiNERExtractor`, `NonInstructExtractor`). Frontier and GLiNER-plus-Qwen experiment profiles also exist, but are not the default application extraction path.

6. **Normalizes entity mentions.** **Verified:** exact type-specific alias matches are mapped to canonical concepts; otherwise, MiniLM embeddings and cosine similarity may map a mention at a 0.84 threshold; unmatched mentions preserve a Unicode-normalized surface form. Original mention text, NER confidence, normalization method/score, and configured identifiers are retained (`pipelines/ingestion/non_instruct.py`, `TerminologyNormalizer`, `SemanticConceptIndex`, `NormalizedMention`). The terminology file currently contains nine curated concepts (`data/terminology/biomedical_aliases_v001.json`).

7. **Scores typed relationship candidates without a generative extraction model.** **Verified:** candidate entity pairs must co-occur in a sentence or adjacent-sentence window and be no more than 300 characters apart. For one of 11 ontology relations, confidence combines prototype cosine similarity (0.50), a lexical cue (0.25), proximity (0.10), and mean entity confidence (0.15). Thresholds, a semantic floor, basic negation rejection, endpoint directions, evidence text, and best-candidate deduplication are applied (`pipelines/ingestion/non_instruct.py`, `RELATIONSHIP_SPECS`, `RelationCandidateScorer`, `accepted_relationships`).

8. **Validates and converts candidates to graph records.** **Verified:** `validate_extraction_output` rejects unsupported types, invalid directions, missing evidence, and relationship confidence below 0.50 or above 1. Entity IDs are deterministic type-plus-slug values; relationship IDs hash endpoints, relation, PMCID, chunk, and evidence. Each edge records evidence, confidence, PMCID/PMID, chunk, extractor, model, prompt version, and timestamp (`pipelines/ingestion/validation.py`).

9. **Loads an idempotent property graph.** **Verified:** Neo4j receives one Paper node per document, biomedical nodes merged by deterministic ID, Paper-to-entity `MENTIONS` edges, and validated biomedical edges merged by relationship ID. Schema constraints enforce unique node IDs and indexes support names and aliases. Graph-run provenance is added to nodes and edges (`pipelines/ingestion/neo4j_loader.py`, `load_processed_record_with_session`; `packages/graph/schema/001_initial_schema.cypher`).

10. **Transforms a question into a ranked evidence set.** **Verified:** `GraphRetriever` expands question terms with aliases and definitions, finds starting nodes through a Neo4j full-text index or substring fallback, retrieves direct paths or—only when path language is detected—two-hop paths, and ranks them with term overlap, concept coverage, relation cues, path structure, and confidence. Up to 12 records can include graph edges and as many as three curated local definitions. This is Cypher-based heuristic graph retrieval, not vector chunk retrieval (`packages/qa/retrievers.py`, `GraphRetriever`).

11. **Builds a constrained answer representation.** **Verified:** retrieved edge records carry endpoints, type, evidence excerpt, confidence, paper/chunk provenance, and path order. Some direct or definition questions are answered extractively; otherwise Qwen 2.5 7B Instruct is prompted to use only the evidence and return schema-constrained JSON with answer, sources, reasoning path, confidence, and abstention (`packages/qa/answerers.py`, `GraphRAGAnswerer`; `packages/qa/prompts.py`).

12. **Evaluates graph construction separately from QA.** **Verified:** extraction predictions are exact-matched to a reviewed five-paper, 43-chunk gold set for entity and relationship precision/recall/F1. QA measures retrieval success, fact/entity/relation coverage, path completeness, citation support, unsupported answers, and abstention. DVC pins parameters, dependencies, metrics, and outputs; MLflow logs parameters, metrics, and artifacts (`pipelines/annotation/evaluation.py`; `pipelines/qa/evaluation.py`; `experiments/dvc.yaml`).

# Deliverable 1 — Capstone Paper

## MedGraphRAG: Transforming Biomedical Literature into Traceable Graph Evidence for Question Answering

### 1. Problem and Project Overview

Biomedical literature is rich in findings but difficult to query directly: relevant claims are distributed across long articles, terminology varies, and relationships are expressed in prose rather than a consistent database schema. MedGraphRAG investigates whether transforming unstructured articles into typed, evidence-bearing graph facts can make retrieval more targeted and answers more inspectable. The project includes an end-to-end web application, API, local models, Neo4j, and experiment infrastructure, but its central data-science contribution is the sequence of representations between a PMC article and a supported answer.

### 2. Data Source and Initial Representation

The source corpus is a curated benchmark of 30 PubMed Central identifiers focused on cardiovascular disease, lipids, statins, fibrates, and omega-3 fatty acids. The current non-instruction ingestion manifest reports 28 successful documents, 231 chunks, 3,046 per-article deduplicated entity records, and 207 relationship records; two records were skipped because NCBI returned no BioC result. This is a purposeful topical seed set, not a representative sample of all biomedical literature.

For each PMCID, the pipeline downloads BioC JSON from NCBI and preserves the raw response. BioC supplies document metadata and passage objects. Parsing creates an in-memory representation of the first BioC document's title, identifiers, year, journal, DOI, authors, passage section/type/source offset, and text. It collapses repeated whitespace, drops empty passages, and joins the remaining text with blank lines. The processed artifact later stores chunk-level offsets and derived sections, not the original passage records. Existing BioC annotations, relations, and sentence structures are not used downstream. This simplification makes deterministic segmentation possible, but it loses markup, rich layout, supplied annotation objects, original passage offsets in the processed representation, and potentially information contained in additional BioC documents.

### 3. Text Segmentation and Representation

The main ingestion pipeline divides the contiguous text into windows of at most 6,000 characters with 500-character overlap. If possible, a boundary moves backward to a space after 60% of the maximum window. Each chunk retains a stable PMCID-based ID, order, global character start/end, primary section and type, overlapping source sections, and text.

Segmentation bounds model input and localizes extracted evidence. Overlap reduces the chance that a fact cut at one boundary disappears entirely. The trade-off is representational: smaller windows isolate claims and reduce computation per call but lose distant context; larger windows preserve more context but introduce more candidate entities and ambiguous pairings. Character overlap duplicates content and may generate repeated candidates, later controlled by deterministic IDs and deduplication. Cross-chunk relations are not reconstructed, so a relationship whose endpoints never share one extraction window is lost.

### 4. Unstructured Text to Structured Biomedical Information

The implemented ontology contains five biomedical node types—Drug, Condition, Symptom, RiskFactor, and Biomarker—plus Paper. Its extracted relation vocabulary is TREATS, PREVENTS, REDUCES, INCREASES, ASSOCIATED_WITH, HAS_ADVERSE_EFFECT, CAUSES, HAS_SYMPTOM, INCREASES_RISK_OF, INTERACTS_WITH, and CONTRAINDICATED_FOR; `MENTIONS` is generated during graph loading.

The application's default graph-building profile is non-generative. GLiNER-BioMed identifies typed mention spans at a 0.50 threshold. A small terminology resource then performs exact alias normalization or semantic matching with normalized MiniLM embeddings and cosine similarity at 0.84; unmatched text keeps a cleaned surface name. This converts variants such as “LDL-C” and “low-density lipoprotein cholesterol” to “LDL cholesterol,” while retaining the original mention and normalization method.

Relations are generated from typed pairs occurring within a sentence or two-adjacent-sentence evidence window, limited to 300 characters. A score combines semantic similarity to a relation prototype, lexical cues, proximity, and entity confidence with weights 0.50/0.25/0.10/0.15. Type-specific thresholds, a semantic floor, and a simple negation pattern filter candidates. The validator then requires an allowed type and direction, evidence text, and confidence of at least 0.50.

A reviewed project example begins with: “continuing risk despite optimal LDL-C reduction on statin monotherapy remains high.” The structured interpretation is Drug=`Statins`, Biomarker surface=`LDL-C`, normalized Biomarker=`LDL cholesterol`, and `(Statins)-[:REDUCES]->(LDL cholesterol)`, with the sentence excerpt and chunk ID attached to the edge. This example is from the human-reviewed gold set; it illustrates the target representation, not a claim that every current extraction is correct.

### 5. Structured Records to Knowledge Graph

Validated entities receive deterministic identifiers such as `drug:statins` and `biomarker:ldl_cholesterol`. Relationship identifiers hash the endpoints, type, PMCID, chunk, and evidence. Neo4j merges Paper and entity nodes by ID, creates `MENTIONS` from each paper to its extracted entities, and creates typed biomedical edges. Nodes and edges carry graph-run provenance; fact edges additionally preserve confidence, evidence, PMCID/PMID, and chunk.

The graph changes what is directly queryable. Instead of scanning all prose for a drug and outcome, retrieval can traverse explicit typed connections, combine two edges into a path, and return the source excerpt for inspection. Name-based identity merging reduces duplicates across papers, although surface-slug IDs alone are not full biomedical entity resolution: synonyms absent from the small terminology file can still create separate nodes, while ambiguous names can be incorrectly merged.

### 6. Knowledge Graph to Question-Answering Context

Question processing is graph-first but not embedding-based. Terminology aliases and curated definitions expand question terms. Neo4j full-text search identifies starting entities, with case-insensitive substring matching as a fallback. Cypher retrieves non-`MENTIONS` edges; explicit “path,” “connect,” or “multi-hop” language enables two-hop traversal. Candidate paths are heuristically ranked using endpoint overlap, concept-group coverage, edge text overlap, relationship cues, path features, and confidence. The default maximum is 12 evidence objects, including up to three curated definitions.

Each object is a compact retrieved representation: source node, relation, target node, evidence excerpt, confidence, article/chunk provenance, and path order. Direct cases may be answered extractively. Otherwise Qwen 2.5 7B Instruct receives only these records and must return schema-constrained JSON or abstain. Unlike conventional vector RAG, the current system does not retrieve semantically similar text chunks; it supplies explicit graph paths and local definition records. This improves structural traceability but makes answer quality dependent on extraction, normalization, and graph coverage.

### 7. Evaluation and Experimentation

Graph construction is evaluated on a reviewed set of five papers and 43 chunks containing 1,449 accepted entity labels and 782 accepted relationship rows. Matching is strict: entities require chunk, type, and normalized name; relationships additionally require type and both typed endpoints. Precision measures the share of predicted records that match gold, recall the share of gold recovered, and F1 balances them.

The latest saved full current non-instruction run achieved entity precision 0.551, recall 0.507, and F1 0.528; relationship precision 0.082, recall 0.091, and F1 0.086. An earlier frontier reference achieved entity F1 0.655 and relationship F1 0.484, but the set is small, development-oriented, and partially LLM-adjudicated, so it is not an unbiased protected benchmark. The low current relation score identifies the major bottleneck: plausible entities do not guarantee correct direction and semantics between them.

QA is evaluated separately because a correct graph can still be poorly retrieved or summarized, while a correct answer may occasionally arise from incomplete evidence. The latest six-question draft development run recorded retrieval recall 0.333, answer accuracy 0.333, citation support 0.667, unsupported-answer rate 0.500, and multi-hop retrieval recall 0.000. These are diagnostic, not generalization claims. DVC makes code, parameters, gold inputs, and outputs reproducible; MLflow records configuration, aggregate/per-type metrics, and artifacts. Per-call duration is audited for extraction, but aggregate latency and monetary cost are not yet formal evaluation metrics.

### 8. Conclusions

MedGraphRAG operationalizes a sequence of transformations: BioC biomedical documents become cleaned text, overlapping chunks, normalized entity and relation records, a provenance-bearing knowledge graph, ranked evidence paths, and finally cited or abstaining answers. The project demonstrates a complete experimental system and, importantly, exposes where information is gained and lost. Structure, identity, and traceability are gained; document layout, cross-chunk dependencies, uncaptured concepts, and uncertain nuance may be lost. The immediate priorities are relation error analysis and calibration, schema–gold alignment, broader entity normalization, a larger PMCID-split holdout set, a working vector/chunk-RAG baseline, cross-chunk relation handling, and formal latency/cost reporting.
